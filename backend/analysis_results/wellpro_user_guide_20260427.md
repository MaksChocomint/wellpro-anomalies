# Руководство пользователя

## WellPro Anomalies

### Назначение системы

WellPro Anomalies - дипломный прототип информационной системы для мониторинга буровой телеметрии, детекции и анализа аномальных показаний сенсорных датчиков буровых установок. Система предназначена для инженерного просмотра исторических рейсов и для потоковой имитации real-time наблюдения по историческим данным.

Пользователь системы получает следующие возможности:

- выбрать объект мониторинга в иерархии «компания -> месторождение -> куст -> скважина -> буровая»;
- запустить потоковый режим анализа;
- загрузить локальный TXT-файл буровой телеметрии;
- выбрать метод обнаружения аномалий;
- настроить окно анализа и порог метода;
- просматривать графики 12 параметров бурения;
- получать визуальные уведомления о найденных аномалиях;
- открывать итоговую сводку по локальному анализу;
- сохранять найденные аномалии в базу данных.

### Целевая аудитория

Система ориентирована на следующих пользователей:

- бурильщик или оператор панели, которому нужен наглядный экран мониторинга;
- инженер по бурению, анализирующий графики и подозрительные участки;
- супервайзер или аналитик, просматривающий результаты по историческим рейсам.

### Режимы работы

В системе предусмотрены два основных режима.

#### Потоковый режим

Потоковый режим предназначен для визуального наблюдения за телеметрией по мере поступления точек. В текущей версии проекта реальный промышленный поток не подключен; вместо него используется WebSocket-симуляция на базе исторических TXT-файлов.

Этот режим полезен, когда нужно:

- посмотреть, как развивается подозрительный участок во времени;
- сравнить поведение разных методов в режиме последовательной подачи данных;
- продемонстрировать работу системы как панели мониторинга.

#### Локальный анализ файла

Локальный режим предназначен для загрузки и анализа полного файла рейса. После обработки пользователь получает графики, список аномалий и итоговую сводку по параметрам.

Этот режим полезен, когда нужно:

- быстро проверить отдельный рейс;
- сравнить методы на одном и том же наборе данных;
- подготовить материал для инженерного разбора или отчета.

### Основной порядок работы

#### Шаг 1. Открытие системы

После запуска приложения пользователь попадает на стартовый экран выбора бурового объекта. На экране отображаются связанные справочники компаний, месторождений, кустов, скважин и буровых.

#### Шаг 2. Выбор объекта мониторинга

Для начала работы необходимо последовательно выбрать:

1. компанию;
2. месторождение;
3. куст;
4. скважину;
5. буровую установку.

После выбора пользователь нажимает кнопку запуска мониторинга.

#### Шаг 3. Выбор режима работы

На основном экране можно:

- запустить потоковую симуляцию;
- загрузить локальный файл;
- вернуться к real-time режиму;
- остановить текущую симуляцию;
- перейти к итоговой сводке по локальному анализу.

#### Шаг 4. Выбор метода анализа

Пользователь может выбрать один из четырех методов:

- «Z-score»;
- «LOF»;
- «FFT»;
- «AMMAD».

Для каждого метода доступны настройка порога и размера окна. В интерфейсе «AMMAD» отмечен как рекомендуемый метод для буровых параметров.

### Краткая логика методов

#### Z-score

Подходит для поиска резких выбросов относительно локального среднего. Лучше всего работает там, где важны единичные скачки.

#### LOF

Подходит для поиска локально редких конфигураций значений. Полезен на каналах с неравномерной плотностью наблюдений.

#### FFT

Подходит для поиска колебательных и пульсирующих режимов. Особенно информативен для давления, расхода, момента и оборотов ротора.

#### AMMAD

Является гибридным методом, который учитывает:

- статистическую атипичность;
- локальную плотность;
- частотные признаки;
- физические пределы параметров;
- контекст бурения, включая рост глубины и залипание каналов.

Для практического использования в текущей версии системы «AMMAD» следует считать основным методом.

### Работа с графиками

На основном экране пользователь видит графическую сетку параметров. Для удобства работы доступны:

- скрытие и показ отдельных параметров;
- включение всех графиков или отключение всех графиков;
- выбор объема видимых точек;
- слежение за последними значениями;
- полноэкранный просмотр отдельных графиков.

При анализе важно помнить, что буровая телеметрия интерпретируется в контексте. Подозрительность участка определяется не только абсолютным значением, но и его связью с глубиной, соседними параметрами и характером режима.

### Интерпретация состояния системы

В системе есть два основных статусных сообщения:

- «Нормальная работа» - на текущем фрагменте не выявлено событий, отмеченных выбранным методом;
- «Аномалия обнаружена» - один или несколько параметров на текущем участке выделены как подозрительные.

Также интерфейс показывает источник данных:

- «Real-time» - потоковая симуляция;
- «Локальная симуляция» - анализ загруженного пользователем файла.

### Просмотр аномалий

При обнаружении событий пользователь может открыть окно аномалий. В нем отображаются:

- время события;
- имя параметра;
- значение;
- выбранный метод анализа.

Если событий много, список разбивается на страницы.

### Итоговая сводка по локальному анализу

После анализа файла пользователь может открыть итоговую сводку. В ней содержатся:

- имя обработанного файла;
- выбранный метод;
- параметры метода;
- общее число аномалий;
- распределение аномалий по 12 параметрам;
- список найденных событий.

Сводка особенно полезна для ретроспективного анализа рейса и сравнения методов между собой.

### Сохранение аномалий в базу данных

Если найденные события нужно сохранить для дальнейшего использования, пользователь может инициировать пакетное сохранение. Система отправляет список аномалий на backend, где они связываются с буровой, методом и конфигурацией метода.

Повторно одна и та же пара «измерение + конфигурация метода» не дублируется.

### Требования к входным данным

Для локального анализа рекомендуется использовать TXT-файлы, совместимые с текущим парсером системы:

- табличный формат с колонкой времени;
- табуляция как разделитель;
- возможные кодировки «utf-8», «utf-8-sig», «cp1251», «cp866»;
- десятичная запятая допустима.

Если обязательный столбец времени отсутствует, файл не будет обработан.

### Практические рекомендации пользователю

1. Для первичного инженерного просмотра целесообразно использовать «AMMAD».
2. Для исследования резких выбросов можно дополнительно смотреть «Z-score».
3. Для проверки пульсаций давления или расхода полезно сравнить результат с «FFT».
4. Если в локальном анализе событий слишком много, стоит проверить, не выбран ли слишком чувствительный метод или слишком малый размер окна.
5. Наличие аномалии не означает автоматически аварийную ситуацию; это признак участка, требующего внимания инженера.

### Ограничения пользовательской версии

- система не подключена напрямую к промышленному API WellPro;
- потоковый режим строится на исторических файлах;
- экспертное подтверждение аномалий в интерфейсе пока не реализовано;
- в текущей версии отсутствует ролевая модель пользователей.

### Типовой пользовательский сценарий

Пример типового сценария работы:

1. Пользователь выбирает буровую.
2. Включает «AMMAD».
3. Запускает потоковый режим.
4. Отслеживает графики давления, расхода, момента ротора и глубины.
5. При появлении тревоги открывает список аномалий.
6. При необходимости переключается на локальный анализ полного файла рейса.
7. По итогам локального анализа открывает сводку и сохраняет выбранные события в БД.

### Заключение

Система WellPro Anomalies предназначена для того, чтобы упростить инженерный просмотр буровой телеметрии, сделать подозрительные участки более заметными и уменьшить объем ручной фильтрации. Наиболее практичным методом в текущей версии проекта является «AMMAD», поскольку он лучше учитывает специфику буровых данных, чем одиночные статистические и частотные методы.
